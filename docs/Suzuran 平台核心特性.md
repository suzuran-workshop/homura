# Suzuran 平台核心特性

Suzuran 是一个 AI 原生（支持 MCP）的企业级多租户 PaaS 平台，提供强大的用户管理和业务应用通用基础能力（如鉴权、流程引擎、对象存储等）。

另有这些特性：

- 介绍 OpenSuzuran，AI + 自然语言即可完成平台内从开发到运维全部流程；
- 介绍 HyperFox，全面满足等保 2.0 三级相关要求，可追溯、可隔离、可恢复，全链路可控可信；
- 全面满足 WAI（WCAG、ATAG、UAAG），体现人文关怀；
- 核心节点支持 Serverless 架构，下一代计算范式，提供更高服务可用性。

## 用户（User）、组织（Org）、部门（Dept）、角色（Role）管理

**用户**是访问本系统的自然人的化身，用户到自然人的映射必然是一对一的。原则上用户的登录键是全局唯一的，登陆需要 登录键和密码 或者 OAuth。

**组织**是现实中企业/机构的抽象，是用户和**部门**的集合。组织内可以存在多个部门，组织架构本身是一个特殊的部门。部门下可以存在部门。每个部门下可以有多个用户。组织架构之间可以存在从属关系，这种情况下组织架构内资源共享。

一个用户可以同时存在于多个组织内，这意味着登陆时将需要选择自己存在的组织（如果有多个组织）。其能访问的资源取决于自己与所在组织。一个用户也可以在多个部门内。

**角色**是组织内一种特殊的属性，往往意味着“流动的职务”。组织与角色之间是一对多关系，用户与角色之间是多对多关系。

## 服务商（Provider）

**服务商**是一种特殊的组织，在系统首次运行的 OOBE 中生成，有且必须只能有一个。

服务商内的用户可以管理系统内所有资源，如其他组织。普通组织内用户无论处于何种职位（部门、角色），都只是对现实情况的映射，他们在系统内被一视同仁：只能使用，不能管理组织的资源。除非服务商用户特别授意或业务应用特别设计。

## 鉴权

一个用户只可以通过以下方式被创建：

- OOBE 创建服务商，并创建全系统第一个用户（root）；
- 服务商手动管理组织时创建用户或根据 Excel 文件批量导入（登录键可被指定）；
- 通过 OAuth 方式从其他 IM OA 平台（企业微信、钉钉、飞书等）批量导入（登录键为 \<platform\>-\<openid\>）；

一个用户一旦被注册，就会生成一个独一无二无法修改的登录键，密码默认为随机 uuid。即只要试图通过账密登录，在没有服务商授意（修改密码）的情况下，无法登录。

一个用户可以增加多个 OAuth 凭证，如多个钉钉账户，或者多个 WebAuthn，或多种方式混搭。

## 流程

**流程**是现实世界异步任务的抽象。业务应用可以构造静态流程或者依赖业务人决策的动态流程（节点处理人不定、单层节点数量不定、节点层数不定）。

Suzuran 必须提供简单便捷的方法来让业务应用创建、撤销、转交流程。并提供合适的数据结构以便于业务应用可视化流程树。

## 对象存储

服务商可以指定对象存储的实现，默认为 MinIO，也可以替换为本地文件系统、阿里云 OSS。已有业务数据时替换实现需要决定：自动将旧数据全部搬迁，或者删除。

服务商可以按照时间、组织、应用组合筛选，管理空间占用（如批量删除文件）。

## 应用程序

**应用程序**是现实世界业务的抽象。服务商可以使用 Agent 调用 OpenSuzuran 快速用 AI 开发符合 Suzuran 要求的应用程序并上传。

OpenSuzuran 仅通过 SSH 公钥判断使用者是否合法。

所有组织（含服务商）可用的应用程序并不相同，数据也不互通，由服务商管控，默认没有任何应用程序可用。特别的，多个相互关联的组织所使用的应用程序是数据互通的。

应用程序通过包名和版本标识自身。向组织分发应用程序时，同包名视为同一应用，行为上是升级；否则视为新建应用。
